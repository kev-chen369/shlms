# V3 领券到商品下单链路

状态：产品 / 技术设计，2026-09-17。关联 [V3 领券页](./images/coupon-center-h5-v3.png)、[前端规格](./13-frontend-ui-spec.md)、[研发计划](./superpowers/plans/2026-09-16-promotion-center.md)。当前已有只读券列表、详情、适用商品接口及可注入的领取请求 / 状态查询边界；仓库没有 H5 前端、渠道券导入、真实领取适配器或已验收的购物转链能力，本设计不表示可以领取或下单。

## 目标交互

用户在 V3 首页或底栏「领券」选择平台 → 查看真实活动与适用范围 → 按券的 `claimMode` 进入下列路径。平台切换清空上一平台的券详情与待跳转状态；未接通的渠道显示空态及开通状态，不提供演示券的可点击领取动作。

- `IN_SITE_VERIFIED`：点击「立即领取」→ 本站取得可信回执 → 显示「已领取 · 去使用」→ 单商品详情或适用商品列表 → 复核券与价格 → 购物 Tracking / 平台下单。
- `PLATFORM_CLAIM`：点击「前往平台领券」→ 取得获批领券承接地址并记录跳转 → 平台登录 / 领券；有独立回执或查询权限才更新为已领取，否则显示「领取结果待确认」，允许返回券规则 / 适用范围查看，不能假定券到账。
- `BUNDLED_OFFER`：点击「领券购买」→ 本站展示券、商品、更新时间与预计金额 → 创建购物 Tracking 并打开渠道商品加券承接页；用户在平台按提示领券、结算。本站不自动切为已领取。
- `PLATFORM_ACTIVITY`：美团等活动点击「去平台领取 / 购买」→ 校验城市、业务、终端和活动有效期后打开官方承接页；到店券购买与到店核销、外卖红包领取与订单使用分别看渠道可验证的状态。

返回本站后仅显示已经得到证据的状态；未回流订单不可凭点击自动显示成交或返现。以上 `claimMode` 是本项目的目标模型，须在 M6-01 对各渠道逐项核对授权后确定。

领券成功后保留当前页的「已领取 · 去使用」状态，同时提供商品入口；不自动替用户下单。商品详情是本站的确认页，真正支付仍在对应平台。若渠道要求到其官方页面领取，本站按钮应为「前往平台领券」，并在回到本站前显示「领取结果待确认」，不能仅因打开了外部页面就标记成功。

## 设计分析：平台券如何使用与跳转

本产品定位为优惠发现与导购入口，首期不代替京东、美团、淘宝收银或核销。先识别券的真实领取方式，再决定按钮与承接页，不能把所有平台券都画成本站内「立即领取 → 已领取」。渠道推广链接负责把用户带到获批的商品、领券或活动页面，并保留渠道允许的归因参数；它本身不是已领券或已成交的凭据。

| 场景 | 本站操作及跳转 | 平台侧实际使用 | 本站可确认的状态 |
| --- | --- | --- | --- |
| 渠道授权本站领取并返回可信回执 | 「立即领取」提交幂等请求；成功后展示「已领取 · 去使用」 | 在该券适用商品 / 店铺下单，结算时核对抵扣 | 仅可信回执可标记已领取；订单另待回流 |
| 必须在平台领取 | 「前往平台领券」打开渠道提供的领券页；返回本站时可进入适用商品或规则页 | 用户登录平台、领取到平台账户，并在结算页选券 | 仅打开页面为已跳转；可查询到领取结果才标已领取，否则待确认 |
| 商品与券合一的推广物料 | 「领券购买」打开该商品对应的渠道链接 | 按承接页提示领券或直接进入购买，结算时确认是否抵扣 | 链接生成 / 打开不证明领券；价格与可用性以平台结算页为准 |
| 美团到店券 / 外卖红包 | 「去美团领取 / 购买」进入对应业务和城市的活动页 | 到店券购买后按平台规则到店出示核销；外卖红包在符合条件的订单结算使用 | 购买、支付、到店核销分别记录；只有渠道提供的证据才能确认对应状态 |

京东可从联盟商品与券信息获取物料，并按获批能力生成商品或商品加券的推广链接；不能把普通商品链接或搜索结果中的券额直接视为用户已领券。淘宝联盟的物料接口存在商品加券页面链接，转链、券 ID 等能力可能有单独权限门槛，须按实际获批接口选择承接形式。美团联盟可按获批活动 / 商品券生成长短链接、唤起链接或小程序路径；到家、到店、城市和活动期限需分别校验，不能把美团券统一解释为电商商品券。依据：[京东联盟说明](https://jos.jd.com/jdunion)、[淘宝开放平台物料接口](https://developer.alibaba.com/docs/api.htm?apiId=64758)、[淘宝转链接口](https://developer.alibaba.com/docs/api.htm?apiId=65409)、[美团联盟推广链接接口](https://page.meituan.net/html/1701831845934_13e608/index.html)。这些资料说明可选技术能力，不构成本项目账户已获批的证明。

终端承接由渠道返回的地址和实际环境决定：App 可唤起且协议允许时打开对应 App；未安装或唤起失败时使用获批 H5 回退；微信等受限环境按获批小程序路径或明确提示用户在平台打开。不得由本站拼接未经核验的 Scheme，亦不得承诺每种环境都能直接唤起。外跳前记录平台、活动 / 商品、券、入口和请求号，提示「将在平台领取并支付」；返站可继续查看规则和适用商品，但不以返站或页面打开推断领取成功。

页面按钮按可验证能力命名：本站可核实领取用「立即领取」；平台领券用「前往平台领券」；券与商品同页承接用「领券购买」；无真实活动数据或跳转能力则显示「暂未开放」。券额、门槛、有效期和适用范围必须带来源与更新时间；任何预计券后价和返现都要区分，最终优惠以平台结算页为准。京东 / 淘宝订单回流与美团到店核销的可见程度取决于具体获批接口，不能用购物 Tracking 代替使用或核销证明。

## 券类型与商品去向

| 券适用范围 | 「去使用」目标 | 约束 |
| --- | --- | --- |
| 单商品券 | 对应本站商品详情 | 详情必须保持同平台、同外部商品 ID；核对券与商品仍匹配 |
| 多商品 / 品类券 | 预筛选的适用商品列表 | 用户选择商品后进入详情，不擅自指向展示图中的某件商品 |
| 店铺券 / 平台通用券 | 适用店铺或商品列表 | 无可靠适用商品目录时展示使用说明及官方入口，不伪造关联 |
| 外部平台券 | 按渠道协议前往官方领券页 | 未取得领取回执时不宣称已领取；返站后查询状态或提示待确认 |

券的稳定标识、平台、外部券 ID、适用商品 / 店铺范围、使用门槛、有效期、领取方式、领取上限、规则版本及更新时间来自可信渠道或运营配置。图稿里的券额、商品和日期是演示数据，不能直接灌入生产接口。券与商品的映射由服务端维护；前端不得通过任意 URL 参数决定外跳地址、商品归属或券后价。

渠道物料同步的内部边界已具备事务性发布 / 撤销与证据事件；只有正式授权的渠道核验器提供快照后才可调用。相同证据重放保持原状态，旧证据拒绝覆盖新状态，撤销同时关闭商品映射。当前未接入京东、淘宝或美团的真实核验器，公开目录保持空态；不得通过客户端请求或演示数据触发发布。

## 页面状态与异常

- 未登录：若券需账户领取，登录后仅回跳站内券详情；不重复提交领取。
- 本站可核实领取：可领取 → 领取中 → 已领取 / 已领完 / 已过期 / 不适用 / 结果待确认 / 失败可重试。使用幂等键，重复点击不重复消耗名额；结果不确定时先查询原请求，不盲目重领。
- 平台侧领取 / 商品加券 / 活动：可打开 → 跳转中 → 已打开 / 打开失败；「已打开」仅是跳转事件，不是领取结果。仅在有获批查询或回执时额外显示领取状态；没有此能力时持续提示到平台账户和结算页确认。
- 已领取：按钮变为「去使用」，显示适用范围与剩余有效期。券到期或商品下架后禁用去使用并说明原因。
- 进入商品详情时重新获取价格、券资格与库存 / 上架状态；显示「预计券后价」和更新时间。平台结算页价格、可用券与实际成交金额以渠道最终结果为准，变化时需用户确认。
- 渠道不可用、领券失败、无法核实适用商品或无法生成安全跳转时，只展示原因及重试 / 查看其他商品，不给出虚假成功。

## 接口边界（只读查询与领取请求边界已实现，真实领取和外跳待接入）

- `GET /api/v1/coupons?platform=...`：已实现只读基础版，按平台、城市、业务筛选，分页返回启用、已核验且有效期内的券、适用范围摘要、`claimMode`、动作文案、更新时间；当前无渠道导入数据时为空列表。文案与模式由服务端数据决定，前端不靠平台名称猜测。
- `GET /api/v1/coupons/{id}`：已实现只读详情；城市 / 业务不符、过期、下架、商品券无有效商品或店铺 / 品类券无范围标识时返回 404。不返回未经校验的任意跳转 URL。
- `POST /api/v1/coupons/{id}/claims`：可注入服务与 HTTP 路由已实现，仅用于 `IN_SITE_VERIFIED` 且有获批适配器的券；鉴权且带 `Idempotency-Key`，返回 claimId 和 `PENDING / CLAIMED / QUERY_REQUIRED / FAILED`。生产目前无适配器，POST 路由不注册。不能把模拟调用或打开平台页面当作真实 CLAIMED。
- `GET /api/v1/coupon-claims/{id}`：已实现按已验签本人读取存储状态；跨用户统一 404。注入适配器后，结果不确定只查询原请求，不重复发起领取。
- `POST /api/v1/coupons/{id}/outbound`：目标接口，用于平台领券或活动承接；服务端按券、场景、终端和授权生成受控跳转方案及独立跳转记录。返回地址不含领取成功语义；失败时不得复用过期地址。是否要求用户登录由实际渠道归因与业务规则确定，匿名请求只能携带合法匿名 Tracking。
- `GET /api/v1/coupons/{id}/products`：已实现有效商品映射的分页查询；单商品可由前端进入商品详情，多商品先显示列表。仅提供商品标识和名称，真实价格 / 库存仍待商品接口复核。
- 商品详情沿用 `GET /api/v1/products/{id}` 的目标接口，额外展示适用券及实时规则；购物跳转沿用购物用途 `POST /api/v1/promotions/link` 的目标边界，与推广员专用转链分开。正式路径 / 字段在渠道协议和前端技术栈确认后冻结。

外跳目标只能由服务端根据获批渠道配置生成并校验 HTTPS / Scheme / 小程序目标，不接受客户端提供任意 URL。购物 Tracking 应绑定用户（如有）、券、商品、渠道、规则快照和请求号；同键重放不得生成第二条逻辑购买跳转。领券、点击、下单、订单归因、佣金确认及到店核销是不同事件，任何一步都不能代替下一步成功证据。首发前按目标终端分别验收 App 已安装、未安装的 H5 回退、微信内限制、小程序承接、活动失效和返站状态。

## 验收样例

1. 已登录用户领取单商品券，确认领取回执后点「去使用」进入正确平台 / 商品详情，再获安全下单跳转；同键重复领取和重复创建跳转均不产生第二条逻辑记录。
2. 品类 / 店铺券先进入适用列表；无可核实商品时不跳到不相关商品。
3. 未登录、过期、已领完、不适用、商品下架、改价、渠道超时和外部领取结果未知均有明确状态；未知结果查询原请求、不假报成功。
4. 跨用户券领取记录不可读；篡改商品 ID、券 ID 或外跳 URL 不能改变服务端归属；渠道域名和重定向受限。
5. 真实测试账户完成领券回执、可打开商品页、下单跳转与渠道测试订单回流后，才分别记录真实业务验收；模拟测试和设计图不能替代。
6. 京东 / 淘宝商品加券链接跳转后只记录已打开；无领取回执时不得显示已领取。美团活动核验城市和业务，购买成功不能冒充到店核销。
7. App 已安装 / 未安装、微信内、H5 和小程序分别验证合法承接与回退；过期地址、无授权终端及跳转失败须显示明确原因，且不得归因成下单。
