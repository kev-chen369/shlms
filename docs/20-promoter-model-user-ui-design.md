# 万单宝式模型分析与推广中心用户端设计

本设计基于仓库中的 [万单宝模型功能](./万单宝模型功能.md)，分析的是该文档提出的业务方案；未将文档视为万单宝现网产品的完整事实清单。界面使用惠省生活品牌，延续 V2 风格，形成独立推广中心的 4 组、16 个核心页面。

## 1. 模型判断

### 服务对象与核心价值

消费者端帮助用户找优惠并查看购物返现；推广中心帮助推广员选择推广来源、生成专属内容、核对推广订单并收取自身收益。两个入口共享身份、订单底层和资金能力，前台用词与操作重心不同。

推广中心的关键能力是把“这条链接由谁、在哪个推广位生成”关联到回流订单和最终收益。转链成功只证明链接已生成；点击、成交、正确归属和结算需要后续独立证据。首版优先验证京东单渠道从推广位、转链到订单归属的闭环。

### 原方案中仍需定稿的规则

| 问题 | 对用户界面的影响 | 本版设计建议 |
| --- | --- | --- |
| 渠道佣金不等于推广员收益 | 展示全额佣金会让用户误解收入 | 普通推广员突出“我的预计收益/我的实际收益”，不默认展示平台分账明细 |
| 消费者返现和推广收益是否重复建钱包 | 两个余额可能被误加或重复入账 | 同一用户、同一币种使用统一可提现余额，按购物返现/推广收益分账和筛选；这是本方案建议 |
| 推广员自购、受邀用户和推广员角色重合 | 一单是否可以叠加多项奖励尚不明确 | 收益规则增加角色组合与互斥条件；规则未确认时不宣传“自购双重奖励” |
| 匿名买家如何绑定消费者返现 | 能归属推广员不代表能定位买家的站内账号 | 消费者身份无法确认时不得凭推广链接自动分配其返现；对外文案不承诺必得返现 |
| 推广位停用的影响范围 | 历史订单是否继续结算、旧链接是否还能用 | 停用后禁止新建转链；历史数据保留。旧链接行为由渠道能力与明确政策决定，不能承诺撤销所有外部链接 |
| 链接重试与更换推广位 | 同一输入可能带来重复记录或错误归属 | 相同请求重试复用逻辑结果；更换推广位视为新请求。成功页面明确当前推广位 |
| 预计、待结算、已入账口径 | 用户可能把未来收入当余额 | 钱包预计与待结算分开；看板期间预估统计与钱包余额不同，不直接相加 |
| 复制、系统分享和实际送达 | “分享次数”可能夸大触达 | 标注“分享操作”；无可信点击来源时显示缺失，不计算转化率 |
| 退款与入账后冲正 | 负收益、冻结金额和扣回可能难以理解 | 未入账按失效展示；已入账追加调整明细。余额不足时的扣回策略须补充后再实现 |
| 推广中心中的团队权限 | 管理员和成员可见范围不同 | 当前图稿先面向个人推广员；团队视角后续按成员权限独立设计 |

### 分账示例的修正理解

文档示例中的渠道实际佣金 10 元，扣除消费者返现 5 元、推广员奖励 1 元、一级邀请奖励 0.50 元后，剩余 3.50 元。若税费、固定成本尚未扣除，该数值只是分配后剩余金额，不能直接视为净利润。

本版推广员界面中，这笔订单突出“我的预计收益 1 元”；消费者预计返现 5 元仅作单独说明，不计入推广员本人的预计收入。转链阶段展示的是当次预估，实际奖励规则须按约定的订单创建或归属时点形成快照；生成链接不等于已锁定最终到账金额。

## 2. 信息架构与角色入口

首页渠道快捷入口下方设置“AI 帮我选 / 推广赚钱”并排卡片，推广入口位于推荐商品上方。[查看首页设计](./images/home-promoter-entry-v2.png)及[交互说明](./images/home-promoter-entry-v2.prompt.md)。

![首页推广中心入口](./images/home-promoter-entry-v2.png)

消费者“我的” → 推广中心：未开通显示申请页；审核中显示申请进度；已启用进入工作台；停用显示原因、申诉/客服与允许查看的历史数据。

推广中心采用独立四栏导航：

| 导航 | 主要任务 | 可到达的子页面 |
| --- | --- | --- |
| 工作台 | 快速转链、查看近期表现 | 推广位、新建推广位、转链、商品确认、结果、分享文案、数据 |
| 活动 | 浏览已开放的推广活动 | 活动选择、推广位选择、活动转链 |
| 订单 | 查看订单归属与自己的收益 | 订单筛选、收益详情、查单 |
| 我的 | 管理推广资料与资金 | 推广资金明细、结算记录、到账账户、提现申请与记录 |

保留“返回省钱首页/切回消费者版”。消费者原有五栏导航不与推广中心四栏混用。登录沿用 [简化版 V3](./images/user-ui-login-simple-v3.png)。

## 3. 功能—页面—数据关联

| 功能编号 | 页面 | 关键数据与操作 | 原文档/接口关联 |
| --- | --- | --- | --- |
| P-01 | 申请开通 | 名称、推广场景、协议、提交审核 | 原文 4.1；申请与审批接口待补 |
| P-02 | 推广工作台 | 期间、推广位、转链次数、有效订单、个人预估收益 | 4.9；GET /api/v1/promoter/dashboard |
| P-03 | 推广位管理 | 名称、场景、默认位、渠道可用状态、停用 | 4.2；GET /api/v1/promotion-positions |
| P-04 | 新建推广位 | 名称、场景、设为默认、渠道待配置状态 | 4.2；POST /api/v1/promotion-positions |
| P-05 | 万能转链 | 主动粘贴内容、推广位、分享场景 | 4.3；POST /api/v1/promotions/convert |
| P-06 | 商品确认 | 识别结果、券后价、本人预计收益、推广位更换 | 4.3、4.7；需补只读解析预览接口，确认前不重复创建推广链接 |
| P-07 | 转链结果 | 商品、有效期、推广位、复制链接、重新转链 | 4.3；GET /api/v1/promotion-links/{id} |
| P-08 | 分享文案 | 面向消费者的文案、复制操作、同源归属 | 4.5；share-artifacts / share-events |
| P-09 | 推广活动 | 已开放活动、有效期、明确选中活动与推广位 | 4.4；活动目录接口待补 |
| P-10 | 推广订单 | 日期/渠道/推广位筛选，订单和收益双状态 | 4.6；GET /api/v1/promoter/orders |
| P-11 | 订单收益详情 | 本人收益、归属来源、阶段、脱敏订单号 | 4.6、4.7；需补带所有权校验的推广订单详情接口 |
| P-12 | 推广数据 | 同口径期间指标、趋势、缺失数据说明 | 4.9；GET /api/v1/promoter/dashboard |
| P-13 | 我的推广 | 推广身份、统一余额、推广资金分类 | 4.8；wallet / promoter/earnings |
| P-14 | 结算记录 | 批次、订单数、个人实际收益、入账时间 | 4.8；批次及明细接口待补 |
| P-15 | 提现申请 | 可用额、本人到账账户、金额、手续费、冻结结果 | 4.8；POST /api/v1/withdrawals |
| P-16 | 提现记录 | 独立申请、处理状态、失败解冻、查看原因 | 4.8；提现列表及详情接口待补 |

原文只定义 convert 接口，但设计中存在“识别/预览 → 确认生成”两步。建议增设只读解析接口，返回短时有效的解析结果引用；convert 再复核商品、权限及推广位，不能直接信任前端传回的价格和收益。

海报、二维码、小程序卡片等与原文阶段四一致，本版文案页以未开放显示。停用或未授权的推广位不可用于转链；用户在等待时切换了推广位，需要重新校验。

## 4. 关键交互与验收

- 粘贴由用户主动触发；空输入、无法解析、非支持渠道分别给出明确提示，并保留输入。
- 无推广位时转链按钮引导新建；有默认位也显式显示选择结果；渠道未配置时禁止生成。
- 生成中防止重复提交；请求重试使用同一幂等键；更换内容、推广位或分享场景时使用新请求标识。
- 复制成功只提示“已复制”，不提示“已发送”；对外文案不泄露推广员收益和内部标识。
- 订单已完成而收益待结算属于正常组合；退款后原始交易和调整记录仍可查看。
- 图中活动页“已选择活动”在开发时必须显示所选活动名称，未选择时不能直接转链。
- 看板示例 7 天有效订单 1+2+3+2+4+3+3=18。示例订单与结算批次用于分别说明界面，不作为一套完整账簿。
- 统一可提现 128.60 元，申请提现 100 元后冻结 100 元，剩余可提现 28.60 元。只有确定失败才解冻，网络超时继续查证结果。
- 看板同期预计收益、已入账收益、钱包可提现余额是不同统计口径，不能直接求和。

## 5. 研发次序与图稿边界

第一批实现 P-03～P-08：推广位、解析预览、转链持久化、链接与文案分享，复用已有 Tracking/JD 适配边界。账号开通权限必须在服务端校验。

第二批实现 P-10、P-11 与可验证的数据指标：订单同步、精确归属、双状态和查单，依据真实回流订单验收。

第三批实现 P-13～P-16：推广奖励规则快照、不可变账务、结算批次与统一钱包提现。

推广活动聚合、素材扩展和团队管理按后续阶段推进。模型已经有基础方向，但还需补齐上述预览、审核、批次等契约，不能把已有基础转链接口等同于完整平台。

本轮交付 16 个核心页面的高保真概念稿；审核中/停用、链接失效、权限不足等需要按上述规则补组件状态。尚未绘制完整团队端、素材海报编辑器和审核后台。部分生成辅助文案、日期、图标及跳转细节需按正式组件规格收敛。数据均为演示，图片不等于已经实现的交易功能。
