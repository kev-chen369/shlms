# 管理后台设计

- 总览：GMV、有效订单、佣金、返现、毛利、退款率、漏单率和同步延迟。
- 渠道：账号状态、推广位、权限清单、健康检查、同步水位与熔断。
- 商品/活动：上下架、排序、地域、终端、有效期和内容审核。
- 订单/佣金/对账：原始数据、标准化结果、状态时间线和差异处理。
- 钱包/提现：只读流水、冻结、审批和付款结果；不提供直接改余额。
- 客服/风控：漏单申诉、证据、风险命中和处置记录。

采用 RBAC 和最小权限。财务、风控、客服、运营和渠道管理员职责分离；密钥仅允许受限角色轮换。资金、密钥、佣金规则、封禁和人工归因操作记录前后值、操作者、审批者与原因。

## 推广中心后台配套（待开发）

2026-09-16 实现进展：已提供带独立管理员权限的审核 / 停用服务和可注入 HTTP 路由；权限分别为 `promoter:review`、`promoter:disable`，禁止管理员操作本人推广资格。并发状态变更通过身份行锁与版本校验保护，状态及 `promoter_admin_audits` 同事务提交；审计包含操作者、操作、原 / 新状态、原因、时间和请求指纹，禁止 UPDATE / DELETE。幂等键按管理员和操作隔离，相同请求返回原操作结果，不回改当前状态；权限撤销后不能通过重放绕过权限。

当前申请列表接口已实现，独立 `promoter:read` 权限，支持状态筛选和游标分页，返回审核版本号；每人仅显示当前申请，不替代历史审计查询。审核页面和生产管理员认证仍待实现。管理员 ID 必须使用与用户身份一致的规范账户 ID，才能保证禁止自审检查成立，不能接受前端角色声明。

审计表防修改不替代生产数据库权限、备份和外部审计：表所有者仍可能执行 DDL / TRUNCATE，生产应用角色必须禁用这些权限。迁移 down 删除审计数据，不得作为常规生产回退。

京东渠道位映射后台服务已实现：`channel:position:configure` 权限可把内部推广位关联到渠道账户和外部位，配置事件追加记录并支持幂等重放。即使管理员完成配置，状态仍为 PENDING_VERIFICATION；正式渠道核验及管理员页面尚未完成。

增加推广申请审核、推广员停用与原因、内部推广位和外部渠道位配置、推广订单归因查询、收益与结算批次核对。审核提交须携带版本号，重复提交幂等；渠道管理员配置映射，财务核对结算，客服只在授权范围查看脱敏数据，均记录审计。

推广用户端已有核心图稿，审核后台的专用交互稿仍待补齐，纳入[研发计划 M0 / M1](./superpowers/plans/2026-09-16-promotion-center.md)。接口与数据边界见[推广中心详细设计](./21-promotion-center-detailed-design.md)，不允许通过后台直接改钱包余额或伪造归因证据。
