# V3 京东、淘宝、美团推广系统设计复核

日期：2026-09-17。性质：基于[推广选品与三组续绘界面](./23-multiplatform-promotion-ui.md)的架构方案，不代表接口、渠道权限或真实订单已完成。后续任务见[SYS 计划](./superpowers/plans/2026-09-17-multichannel-architecture.md)及[既有 M0～M7 计划](./superpowers/plans/2026-09-16-promotion-center.md)。

## 结论与范围

建议继续使用当前 Go API + PostgreSQL 的模块化单体，不为三个渠道先拆微服务。把共用的身份、物料、推广位、预览、请求状态、Tracking、订单证据和结算放在内部领域层；京东、淘宝、美团只在适配器层各自实现经授权的能力。用户端的四栏底导航保持不变，推广选品和确认页是「推广」内部页面，不再增加一级导航。

按界面推进的主链是：`推广身份 → 平台及商品/活动 → 物料详情 → 本人且该平台可用的推广位 → 只读预览 → 确认 → 原子预留 Tracking/转链请求 → 渠道取链/查询 → 安全链接/分享 → 渠道订单 → 归因 → 确认收益/结算`。消费者「领券 → 商品下单」使用购物场景与独立权限，不把购物点击冒充推广员分享。

| `preview.Service` 写入 `Channel: "JD"`，报价接口只返回 `ExternalProductID` 和商品价；迁移 000007 限 `channel='JD'` 且商品 / 价格非空 | 淘宝、美团及无单品价的活动不能直接塞进现有预览 | 新增类型化物料与报价 / 活动快照，保留既有京东商品记录及 API 兼容；通过后续迁移扩展，不改写 000007 历史文件 |

## 模块边界

```text
H5（四栏 + 推广内部路由）
  → API/BFF：鉴权、本人资源、能力/状态投影、分页与幂等键
  → 物料目录：平台 × 商品/活动 × 城市/终端 × 有效期/规则版本
  → 资格/推广位：审核状态、本人内部位、外部媒体/位映射与 readiness
  → 预览/转链：只读快照、复核、数据库原子预留与状态查询
  → 渠道适配器：京东 | 淘宝 | 美团（各自的签名、物料、取链和结果能力）
  → Tracking/订单/收益：原始回流、证据匹配、退款、结算与钱包
```

前端不决定「能否生成」。API 返回按 `platform + materialType + media + position + scene` 计算的能力和原因，例如 `NOT_APPROVED`、`POSITION_PENDING`、`QUOTE_UNAVAILABLE`、`ACTIVITY_EXPIRED`、`LOOKUP_UNSUPPORTED`。即使前端显示可用，预览、预留事务和 worker 调用前仍须重验本人资格、渠道位与物料时效。已生成历史可读，不因位停用被删除。

目录应优先从获批渠道 API 或运营审核配置导入，保留来源证据、更新时间与版本；不同平台的外部 ID 只在平台命名空间内唯一。商品、券、店铺和活动是不同物料类型。活动另有城市、业务、终端、起止时间，不能复用必须有价格的商品快照。缺目录权限时允许粘贴受限链接识别，但解析后仍要匹配已授权物料；不做通用网页抓取或任意 URL 转链。

## 请求与数据一致性

2026-09-19 仓储增量：物料Repository.List在只读REPEATABLE READ内使用CheckInTransaction与物料SQL，能力检查和所有分页批次共用一个快照；仅CATALOG且完整Key / Query范围一致才可读。SQL绑定可信本人及范围，CardFor再校验并返回安全卡片；跳过不合法导入，直到找到limit+1合法卡片或耗尽，后批失败不返回已有部分页。NextCursor绑定本人 / 公共筛选、使用最后已返回卡片UUID且仅真实后续项时出现，不是授权凭证。目录可读不等于商品 / 活动取链可用；尚无公开目录API、真实来源导入或生产READY装配。

2026-09-19 综合验收增量：M7-01c-3a实际完整迁移链up / down / up及四路并发验证；3b观察真实relation锁阻塞并提交十类变更，当前跨批读取保持同一旧快照，新请求及旧游标续页看到当前资格 / 能力 / 材料。撤销不回写已开始读取的快照，不声明立即中止全部在途请求；生成仍须最终事务复核。迁移down与账本清理只在临时测试schema，不提供生产重置入口。当前物料 / 能力结构与只读列表已实现，公开目录 / 详情API、前端及真实获批来源仍未完成。

2026-09-19 实施增量：M7-01b 的 `internal/material` 校验内部平台 / PRODUCT或ACTIVITY身份、时效与来源更新时间、明确地域 / 业务 / 终端规则；活动不要求商品价格。可展示卡片白名单不包含内部canonical URL、外部ID、证据或收益，拒绝时不返回材料，复制范围避免调用方改写。可展示不是能力READY或生成权限。真实来源审核、网络URL白名单 / DNS / 重定向、数据库唯一约束与公开目录接口仍待后续任务，不改变现有京东商品预览路径。

1. 预览应引用 `materialId/type/platform/positionId`、规则版本与到期时间；只读查询渠道商品 / 活动信息，不写 Tracking。报价、个人预计收益和消费者返现分别标注来源和更新时间；活动没有可靠价格时不显示数字。
2. 转链请求的数据库事务同时锁定当前资格 / 位 readiness、校验快照版本、写入唯一幂等指纹和 Tracking/请求记录。现有代码在服务端重查资格后才预留，但尚未将渠道 readiness 最终检查收进同一事务；这是开放真实取链前的优先修复点。
3. worker 仅消费已预留请求，以稳定内部请求 ID 与渠道允许的归因字段调用；每个渠道定义「确定拒绝、确定成功、结果未知」映射。数据库中 `FAILED_RETRYABLE` 可投影为界面的「结果待核验」，但在未证明渠道可查询前**不可**理解为允许重发 Create。
4. 成功链接保存受限渠道 URL、生成时间、物料 / 位 / 场景和展示有效期，按获批域名或受控跳转策略校验；只成功状态允许复制。复制、分享、点击、下单、归因、佣金确认和结算分别记录，绝不以一次点击推出收益。
5. 订单同步先持久化渠道原始证据，再按获批的子标识、外部位、订单号与退款更新去重归因。缺可验证个人归因字段时进入待核验，不能仅凭时间 / 金额自动分给推广员；退款、结算和钱包沿用既有独立状态与不可变流水设计。

建议采用新增迁移建立 `promotion_materials`、`channel_capabilities` 与物料快照 / 证据表，并通过显式外键把新型转链请求关联到物料。旧京东商品快照和 Tracking 不原地改义；双读 / 兼容期间先写既有单品路径，再按渠道分阶段切换。签名密钥、完整外链、原始错误和身份数据不放到设计图或公开日志；DNS / 重定向白名单依平台独立配置。

当前最值得先做的不是三套前端按钮，而是：①确定 APP / 网站真实媒体与渠道权限；②建立能力矩阵及统一物料边界；③修正转链预留的最终 readiness 校验；④按渠道证明未知结果是否可查询 / 幂等；⑤取得一条京东单品真实端到端证据。之后再逐平台放开 UI。此顺序是从现有代码约束和官方能力资料作出的工程推断，须以获批账号实测复核。

### M7-01d-1 详情读取增量（2026-09-19）

物料Repository.Get只接可信本人 / 范围 / CATALOG Key和规范物料UUID；REPEATABLE READ只读事务先检查本人资格、位与精确能力，再读取同平台 / 类型物料并执行CardFor。Detail只有可选白名单item、capability和availability；拒绝时无item，无能力不查询物料，缺失 / 跨平台类型统一MATERIAL_UNAVAILABLE，物料失效仅安全原因。零网络 / Tracking / 转链写入，不泄露内部URL、来源ID或审核证据。HTTP可信配置与鉴权装配、选品前端、真实来源和最终生成事务复核尚未完成，目录读取不能当作生成授权。

M7-01d-2a增量：ReadService通过可信部署配置的精确平台 / 类型 / 终端 / 场景映射选择MediaID，输入不能提供媒体、状态或时间。配置复制到私有map，不设通配 / 默认媒体，歧义重复拒绝；无绑定是安全UNCONFIGURED空目录 / 无item详情。有绑定只构造CATALOG完整Key，每次以服务端时间重新走本人资格 / 内部位scene / 有效证据仓储判定，不缓存READY。所选内部位或scene仍是待校验筛选，不是授权凭据；没有真实配置、HTTP路由或来源批准装配。

M7-01d-2b增量：httpapi新增本人目录 / 详情GET，只有Materials和Users依赖同时存在才注册，先解析身份再校验严格白名单及请求范围；媒体和READY不来自客户端。成功或安全域拒绝200，认证401、无效400、存储503，全部读取no-store，错误data:null丢弃部分结果。实现证据是实际路由配合读取接口替身的HTTP契约测试；cmd/api尚未装配物料服务，真实签名验证器 / PG读取链路与部署媒体配置属于d-3，不因此开放真实选品或生成。
